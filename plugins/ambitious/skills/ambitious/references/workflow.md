# Workflow: research, investigate, plan, implement

This is a suggested order for work in this skill. Use it when a task is large, risky, or recurring. For a small or clear task, it is fine to skip ahead.

The order of research, investigation, and planning is flexible. One boundary is not: the user must approve a rewritten request before you implement it. See SKILL.md, "Approval before implementation".

## 1. Research

Find what the work needs before deciding anything.

- Question 1: what a top professional in this field would do that the request does not ask for. Note the sources you used.
- Question 2: the rawest material available, such as logs, original documents, or measurements. Say where each one is.
- Question 3: the methods and tools the field uses.
- Question 4: the outside checks available.

If a raw source does not exist, say so.

## 2. Investigate

Test what you think you know against the raw material.

- List the beliefs the request depends on.
- Test each belief against the raw data.
- Note which beliefs fail, with the evidence.
- List what the data cannot tell you.

## 3. Plan

Write the plan before doing the work.

- Rewrite the request so it asks for what Research found: the expert steps, the raw inputs, the methods, and the outside check.
- List the steps in order, with the tool each one uses.
- Name the outside check that will decide whether the result is right, and what it cannot catch.
- Name anything missing, such as access, data, or software, and how to get it.
- Present the rewritten request and the plan to the user for approval, as described in SKILL.md under "Approval before implementation". Do not start Implement until the user approves.

## 4. Implement

Carry out the plan.

- Work through the steps in order. Note any change from the plan and why.
- Run the outside check. Record the result.
- If the check fails, go back to Investigate.
- Make any change the user has not approved only after approval.
